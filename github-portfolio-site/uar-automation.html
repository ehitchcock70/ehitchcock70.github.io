Automation Rules

Manager Approval Routing

Rule Logic

  1. Trigger: work item created for an access request type.
  2. Condition: Reporting Manager field is not empty.
  3. Action: add the manager as an approver and request participant.
  4. Action: transition to Waiting for Approval.
Triggers Approvals

Offboarding to Access Removal

Rule Logic

  1. Trigger: offboarding request created.
  2. Action: look up the user's original onboarding ticket.
  3. Action: link both tickets for a complete history.
  4. Action: create access removal subtasks per system.
Linked Work Items Offboarding

Periodic Access Review

Rule Logic

  1. Trigger: scheduled rule runs each review cycle.
  2. Action: create a review ticket for each manager.
  3. Action: manager confirms or revokes each user's access.
  4. Action: revocations generate removal tasks for IT.

Issues Solved

Problems found during rollout and how they were fixed.

Manager Access

Managers could not see requests they needed to approve. Adding them as request participants through automation gave them visibility without broad project permissions.

Permissions

Duplicate Approval Emails

Overlapping rules sent the same approval notice more than once. Consolidating triggers and adding conditions stopped the duplicates.

Notifications

Ticket Linking

Offboarding tickets were not tied to the matching onboarding record. Automatic linking now gives auditors the full access history in one place.
