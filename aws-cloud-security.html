Identity & Access Management

Identity is the new perimeter. Locking down IAM is the first and most important step in securing any AWS account.

Account Hardening

How To

  1. Enable MFA on the root user and stop using it for daily tasks.
  2. Delete any root access keys.
  3. Use IAM Identity Center for workforce sign in instead of long lived IAM users.
  4. Grant least privilege with groups and roles, not inline user policies.
  5. Turn on IAM Access Analyzer to flag resources shared outside the account.

Logging & Monitoring

If it is not logged, it did not happen. CloudTrail and VPC Flow Logs provide the visibility needed for detection and investigation.

CloudTrail Setup

How To

  1. Create a multi region trail covering management events.
  2. Send logs to a dedicated, locked down S3 bucket.
  3. Enable log file validation to detect tampering.
  4. Encrypt logs with a KMS key.
  5. Optionally send to CloudWatch Logs for alerting.
CloudTrail S3

VPC Flow Logs

Capture accepted and rejected IP traffic for network investigations.

aws ec2 create-flow-logs \
  --resource-type VPC \
  --resource-ids vpc-xxxxxxxx \
  --traffic-type ALL \
  --log-destination-type s3 \
  --log-destination arn:aws:s3:::my-flow-logs
VPC Network Visibility

Hunting Failed Console Logins with Athena

Query CloudTrail logs in S3 to find failed AWS console sign ins.

SELECT eventtime,
       useridentity.arn,
       sourceipaddress,
       errormessage
FROM cloudtrail_logs
WHERE eventname = 'ConsoleLogin'
  AND errormessage IS NOT NULL
ORDER BY eventtime DESC
LIMIT 50;

Threat Detection

Managed services that analyze logs and configuration to surface threats and misconfigurations.

Amazon GuardDuty

Analyzes CloudTrail, VPC Flow Logs, and DNS logs for malicious activity.

Common Findings

  • UnauthorizedAccess:IAMUser/... credential misuse
  • Recon:EC2/PortProbeUnprotectedPort port scanning
  • CryptoCurrency:EC2/BitcoinTool.B!DNS crypto mining
aws guardduty create-detector --enable

AWS Security Hub

Centralizes findings and scores the account against security standards.

How To

  1. Enable Security Hub in each region in use.
  2. Turn on AWS Foundational Security Best Practices and CIS AWS Foundations Benchmark.
  3. Integrate GuardDuty, Inspector, and Macie findings.
  4. Prioritize failed controls by severity and remediate.
Security Hub CIS Benchmark

Automated Alerting with EventBridge

Route high severity GuardDuty findings to SNS, Lambda, or a ticketing system.

{

  "detail-type": ["GuardDuty Finding"],

Incident Response

Containment and evidence collection steps for common AWS incidents.

Compromised Access Key

How To

  1. Deactivate the key immediately.
  2. Review CloudTrail for every action taken with that key.
  3. Remove any resources or IAM changes the attacker created.
  4. Rotate credentials and confirm least privilege.
aws iam update-access-key \
  --user-name USERNAME \
  --access-key-id AKIAXXXXXXXX \
  --status Inactive
IAM Containment

Compromised EC2 Instance

How To

  1. Attach an isolation security group with no inbound or outbound rules.
  2. Enable termination protection.
  3. Snapshot attached EBS volumes for forensics.
  4. Tag the instance with the incident ID.
aws ec2 modify-instance-attribute \
  --instance-id i-xxxxxxxx \
  --groups sg-isolation
aws ec2 create-snapshot \
  --volume-id vol-xxxxxxxx \
  --description "IR evidence"
